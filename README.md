# prompt-gate 확장판 — 샘플 사이트

초등 프롬프트 리터러시 프로그램(확장판)의 **자유 주제 다회 대화 + 넛지 + 요소 누적 +
교사 관찰 + 안전 호출**을 한자리에서 돌려보는 최소 실행본이다. 설치 없이 표준
라이브러리만으로 뜨고, `ANTHROPIC_API_KEY`만 넣으면 실제 LLM으로 전환된다.

## 실행

```bash
python app.py
# 관리자 허브(나만) → http://localhost:8000/          (ADMIN_KEY 로 로그인)
# 학생용(차시별)   → http://localhost:8000/s/1 … /s/4  (코드 없이 접속)
# 교사 대시보드    → http://localhost:8000/teacher/1    (TEACHER_KEY 로 로그인)
```

기본은 **MOCK 모드**(키 없이도 대화·유도·안전이 그럴듯하게 돈다). 실제 모델로 돌리려면
아래 둘 중 하나로 키를 넣는다.

방법 A — `.env` 파일 (가장 간단, 권장):
`.env.example`을 `.env`로 복사하고 값을 채운 뒤 `python app.py`. 앱이 자동으로 읽는다.
```
ANTHROPIC_API_KEY=sk-ant-...
ANTHROPIC_MODEL=claude-haiku-4-5-20251001
```

방법 B — 환경변수:
```bash
export ANTHROPIC_API_KEY=sk-ant-...          # Windows(cmd): set ANTHROPIC_API_KEY=...
export ANTHROPIC_MODEL=claude-haiku-4-5-20251001
python app.py
```

실 LLM을 쓰려면 먼저 `pip install anthropic`. 포트 변경은 `PORT=9000 python app.py`.

> 실 LLM 호출이 실패하면(모델명 오류·네트워크 등) 자동으로 mock으로 떨어져 데모가
> 멈추지 않는다. 실습 전 본인 키로 한 번 돌려보고 콘솔에 `[chat] LLM 호출 실패`가
> 안 뜨는지 확인하면 안전하다.

## 실습(발표 시연) 준비 — 5분 체크

1. 발표자 노트북에서 `python app.py` 실행. 콘솔에 뜨는 **"같은 와이파이" 주소**
   (예: `http://192.168.0.10:8000`)를 확인한다.
2. 참가자는 **같은 와이파이**에서 그 주소 뒤에 `/s/1` 을 붙여 접속(예:
   `http://192.168.0.10:8000/s/1`) → 본명 입력 후 대화 시작.
3. 발표자 화면(또는 빔프로젝터)에는 `http://localhost:8000/teacher/1` (교사 대시보드,
   TEACHER_KEY 로 로그인)을 띄워 둔다. 참가자가 대화하면 실시간으로 상태가 바뀐다.
4. 시연 사이에 대시보드의 **"실습 초기화"** 버튼으로 기록을 비운다.
5. 인터넷/키 없이도 mock으로 전체 흐름이 돌아가므로, 현장 네트워크가 불안하면
   그대로 mock으로 시연해도 된다.

> 참가자 기기가 접속이 안 되면: 발표자 노트북 방화벽이 해당 포트를 막았을 수 있다.
> 방화벽에서 파이썬/해당 포트를 허용하거나, 안 되면 발표자 화면 하나로 시연한다.

## 노트북 없이 항상 접속되는 주소 만들기 (상시 호스팅)

위 로컬 실행은 **내 노트북이 켜져 있는 동안, 같은 와이파이**에서만 접속된다.
노트북을 꺼도 **학생이 아무 때나 공개 주소(https://…)로 들어오게** 하려면,
코드를 **클라우드에 한 번 올려 두면 된다**(상시 실행). 코드는 이미 `0.0.0.0`에 붙고
`$PORT`를 읽으므로 아래 순서로 그대로 배포된다. 저장소에 `render.yaml`이 들어 있어
설정은 거의 자동이다.

**Render 무료 웹서비스 — 고정 주소, 노트북 불필요 (권장)**
1. 이 폴더를 GitHub 저장소에 올린다.
2. [Render](https://render.com) 가입 → New → **Web Service** → 그 저장소 연결.
   `render.yaml`이 빌드(`pip install -r requirements.txt`)·실행(`python app.py`)과
   모델·쿨다운·차시(1)를 자동 설정한다.
3. 환경변수에 `ANTHROPIC_API_KEY`·`ADMIN_KEY`·`TEACHER_KEY`를 넣는다(비밀값이라
   자동설정에서 빠져 있음). 특히 접근 코드 두 개는 기본값을 그대로 두지 말 것.
4. 배포되면 받는 `https://prompt-gate-xxxx.onrender.com` 이 **항상 살아 있는 학생용 주소**다.
   교사 대시보드는 그 뒤에 `/teacher`. 노트북을 꺼도 주소는 계속 접속된다.

> 무료 플랜은 한동안 아무도 안 들어오면 잠깐 잠들었다가(cold start) 첫 접속 때
> 몇십 초 뒤 깨어난다. 주소 자체는 늘 살아 있으니, 수업 시작 1~2분 전에 한 번
> 열어 깨워 두면 된다. 잠들지 않는 상시 실행이 필요하면 Railway·Fly.io(카드 등록,
> 소액) 같은 유료 옵션으로 같은 코드를 올리면 된다.

**빠른 임시 주소(터널) — 노트북을 켜 둔 동안만**
계정 없이 즉석 테스트만 할 때. 단, 이건 **노트북이 켜져 있어야** 접속되므로
'항상 접속'과는 다르다. 서버를 켠 채 다른 창에서:
```bash
cloudflared tunnel --url http://localhost:8000    # 설치: brew install cloudflared
# 또는:  ngrok http 8000
```
출력에 뜨는 `https://xxxx.trycloudflare.com` 이 임시 학생용 주소다(노트북 끄면 사라짐).

> 어느 쪽이든, 무료 호스팅은 재배포 때 파일이 초기화되어 `logs/`가 사라질 수 있다.
> 샘플 로그를 남기려면 시연 직후 대시보드에서 확인·정리하거나, 운영 시 DB로 옮긴다.

## 접근 구조 — 관리자(나) / 교사 / 학생

한 서버가 1~4차시를 모두 담되, 보는 사람에 따라 공개 범위가 다르다.

| 대상 | 주소 | 접근 |
|---|---|---|
| **관리자(나)** | `/` (허브) | `ADMIN_KEY` 로 로그인. 1~4차시 챗봇·모든 대시보드에 들어가고, 학생 링크를 복사·배포한다. |
| **학생** | `/s/1` ~ `/s/4` | **코드 없이** 링크만으로. 그 차시로 고정(AI 도우미 특성·안내문·예시가 차시에 맞게 나옴). |
| **교사** | `/teacher/1` ~ `/teacher/4` | `TEACHER_KEY` 로 로그인. **URL의 그 차시 대시보드만** 보인다. 허브(전체)에는 못 들어간다. |

운영 방법: 관리자 허브에서 각 차시의 **학생용 링크**를 복사해 학생에게, **대시보드 링크 +
교사 코드**를 교사에게 나눠준다. 지금은 1차시가 완성본이고 2~4차시는 AI 도우미 특성
초안이라, 학생에겐 우선 `/s/1` 만 배포하면 된다.

- **AI 도우미의 차시별 특징**: 되묻기 강도가 1차시 강 → 4차시 없음으로 줄어든다(지원 감소).
  1차시는 AI가 '가장 중요한 하나'만 되묻고 여러 요소를 한꺼번에 요구하지 않는다.
- **접근 코드**는 `ADMIN_KEY`·`TEACHER_KEY` 환경변수로 바꾼다(기본값을 그대로 쓰지 말 것).
- 로그인은 세션 쿠키(브라우저를 닫으면 만료). `/logout` 으로 해제.

> 참고: 교사 코드는 하나를 공유하므로, 교사가 URL의 차시 번호를 바꾸면 다른 차시
> 대시보드도 볼 수 있다(작은 신뢰 집단에는 충분). 차시별로 교사를 완전히 격리하려면
> 차시별 교사 코드/서명 링크가 필요하다 — 필요하면 그 방식으로 확장할 수 있다.

## 구성

| 파일 | 역할 |
|---|---|
| `app.py` | 서버(표준 라이브러리). 한 턴 처리 = 안전→탐지→넛지→AI응답→로그 적재 |
| `detector.py` | 탐지 엔진. 요소 판별·넛지 정책·안전 필터·대화 코더(실시간=사후 공유) |
| `llm.py` | AI 대화 응답. 키 있으면 실 모델, 없으면 mock |
| `static/index.html` | 학생 화면(`/s/<n>`, 차시 주입·고정) |
| `static/teacher.html` | 교사 대시보드(`/teacher/<n>`, 해당 차시만·3단계 알림) |
| `static/admin.html` | 관리자 허브(`/`, 1~4차시 링크·대시보드) |
| `static/login.html` | 접속 코드 입력 화면(관리자/교사 공용) |
| `logs/turns.csv` | 턴 로그. **코딩 시트 '턴별코딩' 탭 스키마와 동일** |

## 동작 확인 포인트

- 유도(스캐폴딩)는 별도 알림이 아니라 AI 응답 속 자연스러운 되묻기로 이뤄진다.
- 담당 차시(`LESSON_SESSION`)에 따라 되묻기 강도가 달라진다(1차시 강 → 4차시 되묻지 않음 = 지원 감소). 지금은 1차시 전용.
- AI가 되물은 다음 턴에 요소가 늘면 계기가 '유도', 스스로 늘리면 '자발'로 기록된다.
- 위험 발화(예: 자해 표현)를 넣으면 AI를 호출하지 않고 교사 호출로 전환된다(fail-closed).
- 한 턴마다 `logs/turns.csv`에 기록이 쌓인다 → 수업 후 코딩 시트에 그대로 붙는다.
- **연속 전송 방지**: 전송 후 5초 동안 버튼이 카운트다운으로 잠긴다. 개발자도구로
  우회해도 서버가 다시 막는다(클라이언트+서버 이중). 초는 `COOLDOWN_SEC`(기본 5)로 조절.
- **이름**: 지금은 **본명**으로 입력받는다(빈칸이면 시작 안 됨). 연구용 로그는 나중에
  익명 ID로 치환한다(아래 주의 참고).

## prompt-gate(FastAPI)로 옮길 때

- `app.py`의 `handle_turn()` 로직을 FastAPI 라우트에 그대로 넣으면 된다.
- `detector.py` / `llm.py`는 프레임워크 독립이라 수정 없이 재사용.
- 세션 상태는 지금 메모리 dict(`SESSIONS`)다. 실제 운영은 DB로 교체.

## 안전 계층 (선행연구 반영)

키워드 단독 필터는 우회·간접 표현을 놓치고 오탐도 난다(내용 조정 연구의 공통 지적).
그래서 3중으로 둔다.
- **Layer 1 — 키워드(입력)**: 빠른 1차 게이트, 위험 시 즉시 교사 호출(fail-closed).
- **Layer 2 — 키워드(AI 출력)**: AI 답도 검사해 위험하면 학생에게 안 보이게 차단.
- **Layer 3 — LLM 2차(입력)**: 키워드가 놓친 맥락·우회 표현을 모델이 다시 판정.
  턴당 LLM 호출이 1회 늘어 비용이 오르므로 `SAFETY_LLM=1`일 때만 켜진다(실 학생용 권장).
사람(교사 대시보드)이 최종 개입하는 human-in-the-loop는 그대로 유지된다.

또한 AI 대화 프롬프트는 정답을 통째로 주지 않고 **필요한 만큼 힌트를 단계적으로** 주도록
지시한다(AutoTutor식 힌트 사다리). 차시별 되묻기 강도는 지원 감소(fading)를 따른다.

## 주의 (연구·수업 투입 전)

- **mock 판별기는 데모 전용**이다. 실제로는 실 LLM + 탐지 엔진 검증 프로토콜
  (요소별 F1, 엔진–사람 κ, 자기일관성)을 통과해야 하며, 그 전까지는 사람 확인을 병행한다.
- 초등 대화 로그는 개인식별정보 마스킹·익명 ID·보관/폐기·학부모 동의를 전제로 처리한다.
  현재 샘플은 **본명**을 그대로 받으므로, 연구 데이터로 쓸 때는 수집 후 본명→익명 ID
  (예: S01, S02)로 치환하고 원본 매핑표는 분리 보관·기한 내 폐기한다. 공개 주소로
  운영할 때는 특히 본명 로그가 외부에 남지 않도록 시연용/연구용 세션을 분리한다.
- 안전 필터는 키워드 기반의 1차 방어다. 실제 운영에선 출력 필터·세션 누적 감시·
  교사 대시보드를 함께 둔다.
